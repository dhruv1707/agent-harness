# Daily Workflow

## Protocol

**1. Pull.** Get top-performing ads for the run's window from the connected sources. Use the
account's primary efficiency metric to rank; if the run context does not name one, ask.

**2. Read the hooks.** For each winner, get the actual creative — transcript, first frames,
or on-screen text. Write down the literal first line and the opening shot. Classify the hook
against the taxonomy in `memory/hook-patterns.md`, and if it does not fit, name the new
pattern and say so.

**3. Find the pattern across winners.** Do not brief ad-by-ad in isolation. State what the
top ads share — a hook family, a format, a claim, a face. That shared thing is what you are
iterating on. If the winners share nothing, say that plainly; it is a real finding.

**4. Brief.** Write iteration briefs against the pattern. Each brief is one shootable
variation, not a menu of options.

## Output contract

Report:

```
## What won — <window>
One paragraph. The pattern across the winners, with ad ids.

## Hooks
| Ad | Hook (verbatim first line) | Pattern | Metric |
Table of the winners. Mark UNVERIFIED where you did not see the creative.

## Briefs
Then the briefs.

## Flags
Anything a human needs to decide: claims to approve, data gaps, source errors.
Omit this section if there is nothing to flag.
```

Each brief:

```
### Brief N — <short name>
**Iterating on:** <ad id> — <one line on what you're keeping and what you're changing>
**Hook:** the exact first line, written to be said out loud
**Open on:** the first shot, concretely
**Then:** 2-4 beats of what happens, in order
**Say:** any required copy or claim, verbatim
**Don't:** the one mistake that would kill this variation
```

## Volume and stopping

Default to 3–5 briefs. More than that and creators cherry-pick, which defeats the test.

Write the briefs, produce the report, and stop. Do not offer to write more, do not ask what
to do next, and do not summarize what you just wrote.
