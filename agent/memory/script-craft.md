# Script Craft

How to write anything a creator reads aloud on camera. Read this before drafting a script
or a brief — not after.

Read it alongside `brand-voice.md` for product facts and approved phrasing, and
`brief-samples.md` for the register. If those are still placeholders, say so in your output
rather than inventing a house style you have not been shown.

## What a script is

A finished piece of spoken copy. First person, past tense, one beat per line, blank line
between beats, ending with `CTA` on its own line. Not a shot list, not a strategy memo. If
it cannot be spoken, it is not finished.

Every approved script runs the same skeleton. An iteration changes the opening and the
specifics, never the skeleton:

1. **Open on a specific private moment.** No product, no premise the viewer must accept.
2. **Escalate in short beats** — the routine, the failed workaround, the thing that kept
   happening.
3. **The turn: a physical realization.** Something concrete she noticed. Not a conclusion,
   a sensation.
4. **Product boilerplate**, dropped in near-verbatim from `brand-voice.md`.
5. **A soft disclaimer** that deflates the claim before it overreaches.
6. **The offer or instruction**, then `CTA`.

Length: roughly the length of the approved samples. Do not pad to hit a beat count.

## How it sounds

- **First person, past tense, one narrator.** She tells what happened to her. Never
  "customers report", never "studies show", never a voice explaining the product.
- **One beat per line.** Short sentences, fragments allowed. The line breaks are the pacing
  — read it aloud and break where you would breathe.
- **Concrete and physical.** A sensation, not a benefit. Never abstract benefit language.
- **Casual asides carry it.** The throwaway line is doing work; polish kills it.
- **Open mid-thought.** Never on the product, never on a compliment, never on a premise the
  viewer has to accept first.
- **Deflate before overreaching.** Undercut the claim on purpose near the end.
- Ellipses mark a trailing thought before a punchline. Em dashes are rare.
- **No second-person instruction inside the script body.** It persuades by telling a story,
  not by telling the viewer what to do. Second person belongs in the closing line and the CTA.

## Borrow the register, not the lines

The samples in `brief-samples.md` teach pacing, where the turn lands, how a claim gets
deflated. They are not a phrase bank.

**Two things are reused word for word, and nothing else is:**

- the product boilerplate in `brand-voice.md`
- an approved claim, exactly as written

Everything else is new writing. Lines from ads that already ran produce a variation that
tests almost nothing, because the viewer who saw the first one is seeing the same images
again. Ad fatigue is partly line fatigue.

Write the same *kind* of concrete physical detail, not the same detail. If a phrase in your
draft appears in a sample, it needs a reason beyond having read it there.

Where this file and a sample disagree about *register*, the sample wins — it shipped, and
this file is a summary of it.

## The brief a creator receives

Each script is headed by two metadata lines and then the script itself. **The metadata is
for the strategist; the body is what gets sent to the creator, so keep it clean — no stage
directions, no bracketed notes, no commentary inside it.**

```
### Script N — <short name>
**Iterating on:** <ad id> — what you are keeping, what you are changing
**Pattern:** <hook pattern from hook-patterns.md>

<the script, one beat per line, ending in CTA>
```

## The ad-review report

When the deliverable is a review of what won rather than a single piece of copy:

```
## What won — <window>
One paragraph. The pattern across the winners, with ad ids. Name the ranking metric you
used. If tag coverage was partial, say what share of spend it covered.

## Hooks
| Ad | Hook (verbatim first line) | Pattern | ROAS | Thumbstop |
The winners. Mark UNVERIFIED where you did not read the creative, and say why —
no cached transcript, untagged, carousel.

## Scripts
The scripts.

## Flags
Anything a human must decide: claims to approve, data gaps, refused approvals, source
errors. Always state transcription cost here — how many were served free from cache and
how many were paid for — so the credit cost of the run is visible. Omit the section only
if there is genuinely nothing to flag.
```

Default to 3–5 scripts. More and creators cherry-pick, which defeats the test.
